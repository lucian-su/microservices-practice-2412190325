## 1. 业务建模（直接复制）

本周实现桌游社活动发布与报名流程。Activity 表示活动，Registration 表示报名，两者通过活动主键建立一对多关系。成员使用学号或社员编号报名，Service 检查活动是否存在、是否已开始、是否重复报名及剩余名额，成功后保存报名记录。数据库通过外键和活动编号与成员编号的复合唯一约束保证关联与报名唯一性。

## 2. 单体应用实现（直接复制）

在原 monolith 工程中完成活动与报名模型、Service、Controller 和六个 REST 接口。通过实际 HTTP 请求验证活动创建、查询、报名及报名记录查询；重复报名和人数已满返回 409，无效参数返回 400，资源不存在返回 404。
