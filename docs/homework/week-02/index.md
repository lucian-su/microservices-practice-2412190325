# Week 02 项目选题与功能规划

## 项目选题

### 项目名称

桌游社活动管理与组队平台

### 业务背景

目前桌游社主要通过 Excel 表格管理桌游信息，并通过微信群发布活动和组织成员报名。随着桌游数量和成员数量增加，逐渐出现桌游信息查询不方便、活动消息容易被聊天记录覆盖、报名人数需要人工统计以及新成员难以快速了解社团活动和其他成员等问题。

因此，本项目计划开发一个桌游社活动管理与组队平台，对桌游信息、活动、报名、组队和评价等内容进行统一管理。

### 目标用户

项目主要包含三类用户：

- 普通社团成员：查看桌游、浏览活动、报名活动、加入队伍和进行活动评价；
- 活动组织者：创建活动、设置时间地点和人数限制、管理报名成员；
- 社团管理员：管理用户、维护桌游信息和管理活动。

### 选题原因

选择桌游社活动管理与组队平台作为本学期课程项目，是因为该项目来源于实际校园社团场景，业务背景明确，同时包含用户、桌游、活动、报名、组队和评价等多个功能模块。

项目规模适中，后续能够继续完成数据库持久化、身份认证、微服务拆分、消息通信、事务管理、系统监控和 Docker 部署等课程任务。

### 项目边界

当前计划实现：

- 用户管理；
- 桌游信息管理；
- 活动管理；
- 活动报名；
- 组队管理；
- 活动评价。

当前暂不实现在线支付、实时语音或视频聊天、复杂智能推荐和商业化运营功能。

## 功能规划

### 用户模块

实现用户注册、登录、个人信息维护、角色管理和活动记录查询。

### 桌游管理模块

实现桌游信息添加、修改、删除、分类查询以及桌游人数和状态查看。

### 活动管理模块

实现活动创建、活动时间地点设置、人数限制、活动报名和活动状态管理。

### 组队模块

实现队伍创建、加入队伍、查看队伍成员以及队伍人数管理。

### 评价模块

实现活动结束后的评价以及成员活动参与记录。

### 核心业务流程

用户登录系统后浏览活动列表，选择活动并查看详细信息。用户确认参加后提交报名，系统判断当前活动是否还有剩余名额。报名成功后用户加入活动队伍并参加线下活动，活动结束后可以进行评价并形成活动参与记录。

### 后续计划

后续课程中计划逐步完成：

- MySQL 数据库持久化；
- JWT 用户认证和权限控制；
- 按照用户、桌游、活动、组队、评价等业务拆分微服务；
- 使用消息队列实现活动和报名通知；
- 处理活动报名过程中的事务一致性；
- 增加日志、健康检查和系统监控；
- 使用 Docker 完成项目部署。
